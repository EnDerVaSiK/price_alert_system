## Описание возникших ошибок и способов их исправления

**Project**

* **Глобальное добавление путей (Коллизия импортов main.py в автотестах)**
  * Проблема: При запуске pytest для проверки всех микросервисов возникали странные ошибки (например, AttributeError или отсутствие папки __pycache__). Это происходило потому, что главный файл каждого сервиса назывался одинаково — main.py. pytest кэшировал первый загруженный модуль main в оперативной памяти и подсовывал его при тестировании последующих сервисов, игнорируя их собственные файлы main.py.
  * **Решение**: В начало каждого тестового файла была добавлена строгая изоляция путей (удаление соседних микросервисов из sys.path) и принудительная очистка кэша импортов Python перед загрузкой целевого модуля:
* **Окружение и зависимости (Windows/MSYS2)**
  * **Проблема** (ModuleNotFoundError): Локальный запуск pytest падал, так как библиотеки (aiogram, sqlalchemy) были установлены только внутри Docker, но не в локальном виртуальном окружении Windows.
  * **Решение**: Перенос запуска тестов внутрь временных Docker-контейнеров через docker-compose run.
  * **Проблема** (Ошибка компиляции Rust/maturin): Пакет pydantic-core не мог установиться в терминале MSYS2 из-за отсутствия готовых бинарников (wheels) и компилятора Rust.
  * **Решение**: Использование стандартного официального образа python:3.11-slim внутри Docker, где установка проходит мгновенно.

**ALL Services**

* Отсутствие в структуре файлов `Dockerfile` для каждого сервиса, что привело к невозможности запуска сервисов через `docker-compose.yml` (Docker не понимал, как собирать образы). Исправлено написанием унифицированного `Dockerfile` для Python-воркеров и отдельного для Node.js.

* Команда для запуска/перезапуска `docker-compose` приводила к кэшированию нерабочих конфигураций. Для полного сброса и обновления кода пришлось использовать принудительную пересборку: `docker-compose up --build --force-recreate`.

* При запуске API Gateway падал из-за отсутствия таблицы `subscriptions` в БД (гонка состояний). Было добавлено событие `startup` в FastAPI для автоматического выполнения `Base.metadata.create_all` через SQLAlchemy.

* При доработках проекта ИИ всячески пытался размазать логику некоторых отдельных частей по нескольким сервисам, что противоречит написанию микросервисной и безопасной архитектуры.

**api-gateway**

* Иногда проскакивала ошибка `Connection refused` при попытке API Gateway отправить задачу в Redis. ИИ жестко закодировал подключение по адресу `localhost:6379`, что в контексте Docker означает обращение контейнера к самому себе. Исправлено на чтение переменной окружения `REDIS_URL` со значением `redis://redis:6379/0`.
* **Архитектура и логика**
  * **Проблема**: Отправка приветственных уведомлений напрямую из api-gateway нарушала принцип микросервисов (шлюз брал на себя работу нотификатора).
  * **Решение**: Добавлена отправка специального события {"type": "welcome"} в очередь queue:notify через Redis, чтобы за все сообщения отвечал только воркер notifier.

**tests**

* **Настройка моков**
  * **Проблема** (lpush Called 0 times): Тесты не видели вызовов к Redis, так как @patch применялся к локальной переменной, а приложение создавало новое подключение.
  * **Решение**: Изменение патча на перехват самого метода создания клиента: @patch.object(main.Redis, 'from_url').
  * **Проблема** (Синхронизация данных в analyzer): Ошибки вида assert 300.0 == 310.0 или несовпадение ID пользователей (реальный_tg_id == 123456).
  * **Решение**: Синхронизация жестко заданных тестовых данных в assert с возвращаемыми значениями моков базы данных и фейковых JSON-ответов.
  * **Проблема** (session.add Called 0 times в api-gateway): Падение тестов проверки записи в базу данных.
  * **Решение**: Точечная замена мока для синхронного метода add на MagicMock() вместо AsyncMock().
* **Асинхронность и aiogram**
  * **Проблема** (RuntimeError: Task pending): Незавершенные корутины после прохождения тестов для Telegram-бота.
  * **Решение**: Замена моков для методов message.answer (которые в aiogram являются асинхронными) с MagicMock на AsyncMock, чтобы тест корректно их "дожидался" через await.
  * **Проблема** (RuntimeWarning: coroutine was never awaited в httpx): Желтые предупреждения из-за метода raise_for_status().
  * **Решение**: Замена мока для объекта HTTP-ответа обратно на синхронный MagicMock(), так как этот конкретный метод в библиотеке httpx не требует await.

## Скриншот успешного прохождения автотестов

Команда запуска тестов с удалением базы данных, которая не привязана к хранилищу данных volumes:

`docker-compose run --rm -e PYTHONDONTWRITEBYTECODE=1 -v .:/project -w /project api-gateway bash -c "pip install -r tests/requirements.txt && pytest tests/ -v -p no:cacheprovider" ; docker-compose down`

## Дополнительные возможности: OpenAPI (Swagger) спецификация

Так как основной интерфейс системы реализован через Telegram-бота (Long Polling), для выполнения требований по документированию REST API была спроектирована архитектура **Admin Backoffice API**. Данный интерфейс предназначен для управления системой извне (например, для панели администратора).

Спецификация написана по стандарту OpenAPI 3.0.3 и сохранена в файле `docs/openapi.yaml`.
